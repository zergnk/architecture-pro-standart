1. Необходимы доработки сайта, интернет-банкинга, АБС, системы кол-центра на стороне банка. 
- Все изменения в рамках используемых в этих системах технологий и стандартов. 
- Заявка на открытие депозита на сайте будет создана в системе кол-центра, для дальнейшей работы с ней менеджером кол-центра (далее процесс обработки не изменился).
- Обмен данными синхронный посредством вызова API.
- Данные АБС, другие систем получаю через запросы к БД АБС.

2. Необходимо реализовать новую систему "Актуальные справочники", которая будет использоваться сайтом и интернет-банком. Система будет также содержать актуальные предложения по депозитам.  
Она нужна для того, чтобы не дублировать логику на сайте и в интернет-банке и не реализовывать прямой доступ к данным в БД системы АБС. Кроме того, 
ядро интернет-банка модифицирует внешняя команда. Система также кеширует данные, чтобы минимизировать количество запросов к чувствительной к нагрузе системе АБС и сокрасить время выполнения запросов, т.к. АБС является медленной системой.<br/>
**Используемые языки и технологии:** Java Spring Boot и СУБД.<br/>**Команда разработки:** специалисты IT-отдела банка.
3. Функционал работы для СМС-кодов подтверждения необходимо реализовать не в ядре интернет-банка.
**Используемые языки и технологии:** Java Spring Boot.<br/>**Команда разработки:** специалисты IT-отдела банка.
4. В системе интернет-банка необходимо реализовать микросервис "Специальные ставки по депозитам", который будет на основе данных из АБС возвращать по запросу для веб-приложения интернет-банка персональные ставки для клиента, если они были для него посчитаны. Если клиент удовлетворяет критериям некоторой категории клиентов, для которой указаны ставки по депозитам, они тоже будут ему отображены..
   Она нужна для того, чтобы не дублировать логику на сайте и в интернет-банке и не реализовывать прямой доступ к данным в БД системы АБС. Кроме того,
   ядро интернет-банка модифицирует внешняя команда. Система также кеширует данные, чтобы минимизировать количество запросов к чувствительной к нагрузе системе АБС и сокрасить время выполнения запросов, т.к. АБС является медленной системой.<br/> 
**Используемые языки и технологии:** Java Spring Boot и СУБД.<br/>**Команда разработки:** специалисты IT-отдела банка.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
1. Реализация асинхронный обмен данными между системами через очередь сообщений могла бы быть более эффективной, но команда не имеет опыта работы с подобными технологиями. 
Т.к. это увеличивает сложность системы, то возрастают риски не уложиться в определенные сроки.
2. Получение данных по интеграции из БД АБС возможно, но нагрузит БД при синхронизации и обновление будут раз в сутки.  
3. Можно было реализовать прямое получение необходимых данных для сайта и интернет-банка. Но это прямой доступ в БД АБС из других систем.

**Недостатки, ограничения, риски**
1. Синхронный обмен в случае отказа одной из систем может привести к полному отказу интернет-банка или сайта.
2. Чтобы не усложнять MVP, заявку на открытие депозита через сайт нужно сохранить в системе кол-центра. Необходимы доработки системы.
